# Native Codex build

Model Guard extends the **official Codex 0.155.1 source** at commit
`be2951ea34f0d295ed0becf97079f92fa5f6950e` (`rust-v0.155.1`).
It is a custom build maintained by this project, not an official OpenAI release.
The normal CLI, app-server, authentication, safety policies, terminal event loop,
code-mode host and provider transports retain their upstream implementation.

The patch series separates routing metadata, native display, its tests, generated
protocol schemas, release packaging, and the update hand-off (`codex update` and the
update banner run `model-guard-codex update` and compare against this plugin's
`release.json` instead of upstream's latest tag). `release.json` pins every patch and distributed
artifact by SHA-256. The release archive includes the upstream Apache license
and NOTICE. The Model Guard repository remains MIT licensed.

The native extension adds an experimental `model/routing/updated` notification.
Its request values are copied from the final Responses request after effort,
endpoint and service-tier normalization. Effective server model disclosures
continue to originate in upstream transport parsing. The response body's
`model` label travels separately as `responseLabel`; it never becomes the
server model. Metadata is transient and the extension does not write
Codex rollouts or inspect login files.

The TUI shares the existing footer and adds space only for a routing, body-label
or repeated reasoning warning, wrapping it when the terminal is narrow. Normal terminal setup and input handling are unchanged.
`/status` explains details. Disabling `model-guard` in Codex disables the display.
A separate remote app-server requires the metadata extension for full evidence.

## Build

The distributed x86_64 GNU/Linux package is built inside the `rust:1.95.0-bookworm`
container, so it requires glibc 2.36+, and uses upstream release optimizations
(thin LTO) with debug symbols disabled. The code-mode host, bwrap, zsh, ripgrep
and the voice runtime directory come from the exact official 0.155.1 standalone
package: the four helpers are checksum pinned, the voice manifest is pinned and
every runtime file it lists is checked against it. Other operating
systems/architectures do not have a published native package in this release.

The helper package is the unaltered official standalone release
(`codex-package-x86_64-unknown-linux-musl.tar.gz` of the pinned tag, or the
`current` directory of a standalone install at that version). Build in a new
directory inside the container; `docker run` needs the plugin checkout, the
official package and an empty work directory mounted:

```sh
docker run --rm -v "$PWD:/plugin" -v "$OFFICIAL:/official:ro" -v "$WORK:/work" rust:1.95.0-bookworm sh -c '
  apt-get update -qq && apt-get install -y -qq pkg-config libssl-dev libcap-dev python3 >/dev/null &&
  python3 /plugin/native/build.py --work-dir /work/build --official-package /official --jobs "$(nproc)"'
```

Outside a container the same `build.py` invocation needs Rust 1.95.0 (rustup
installs it from `rust-toolchain.toml`), a C/C++ compiler, pkg-config, libssl-dev
and libcap-dev, and the resulting package requires the build host's glibc.

`--prepare-only` verifies the source tag and applies the reviewed patches without
compiling. The package checksum in `release.json` verifies the published archive;
local rebuild checksums may differ because build paths and archive timestamps
are not normalized. `build-record.json` records the local result. Reproducible
source inputs are provided; bit-identical cross-machine binaries are not claimed.

The upstream release tag updates workspace package versions to 0.155.1 while its
Cargo.lock retains 0.0.0 for workspace members. The packaging patch carries the
lockfile regenerated by Cargo for those workspace versions. External package
versions, sources and checksums are unchanged. Cargo builds use `--locked`.

## Release

A new official Codex release reaches this package in one loop:

1. The **Codex upstream watch** workflow (daily) opens an issue naming the new
   version and whether each source patch still applies; rebase whatever
   conflicts and set the tag, commit, patch digests and helper digests in
   `release.json`.
2. Dispatch the **Codex native package** workflow, or run the container build
   above; both produce the archive and `build-record.json`.
3. Create release `v<plugin version>` with the archive attached, put its
   `package_sha256` and `binary_sha256` and the download URL into
   `release.json`, bump the four Codex version fields and the release log.

Installed machines then move with `model-guard-codex update`, which brings the
official standalone package to the new pinned version before installing.

## Validate

The release measurements and baseline comparison are recorded in
[`validation.json`](validation.json). A full workspace attempt is blocked by a
missing upstream V8 prebuilt artifact. Host sandbox limitations and release-tag
snapshot mismatches are compared with the pristine upstream source; they are not
reported as passing tests.

Run Rust checks with the upstream runner from `source/codex-rs`:

```sh
just fmt
just test -p codex-api -E 'test(process_sse)'
just test -p codex-core -E 'test(model_routing)'
INSTA_WORKSPACE_ROOT="$PWD" just test -p codex-tui -E 'test(native_guard)'
INSTA_WORKSPACE_ROOT="$PWD" just test -p codex-app-server-protocol -p codex-tui
just test
```

When comparing worktrees with a shared Cargo target directory, explicitly set
`INSTA_WORKSPACE_ROOT` to the source workspace being tested and rebuild changed
crates; cached workspace discovery can otherwise select the other tree.

The tag's `just write-app-server-schema` still names a removed binary. The
upstream schema writer is now an ignored library test; these equivalent runner
commands regenerate the same fixtures:

```sh
export CODEX_APP_SERVER_SCHEMA_ROOT="$PWD/app-server-protocol/schema"
CODEX_APP_SERVER_SCHEMA_EXPERIMENTAL=0 just test -p codex-app-server-protocol --lib \
  -E 'test(=schema_fixtures_tests::write_schema_fixtures_from_env)' --run-ignored only
CODEX_APP_SERVER_SCHEMA_EXPERIMENTAL=1 just test -p codex-app-server-protocol --lib \
  -E 'test(=schema_fixtures_tests::write_schema_fixtures_from_env)' --run-ignored only
```

From the plugin root, Python 3.12+ tests use a development environment:

```sh
python3 -m venv .venv
.venv/bin/pip install --require-hashes -r requirements.lock
.venv/bin/pip install --no-deps -e .
.venv/bin/pip install --require-hashes -r tests/requirements.lock
PYTHONPATH=. MODEL_GUARD_INTEGRATION=1 \
MODEL_GUARD_CODEX_BIN=/path/to/native/package/bin/codex \
MODEL_GUARD_NATIVE_BIN=/path/to/native/package/bin/codex \
MODEL_GUARD_STOCK_BIN=/path/to/official/package/bin/codex \
.venv/bin/python -m unittest discover -s tests -v
```

All inference fixtures use isolated Codex homes and loopback servers, without
real credentials or model quota. PTY tests cover new/resumed/forked conversations,
the Fish `cx resume` command shape, paste and resizing. They compare native and
official terminal modes and verify long responses remain in terminal scrollback.
Claude regression checks remain `tests/run.sh` at the repository root.
